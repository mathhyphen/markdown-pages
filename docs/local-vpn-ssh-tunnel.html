让远程服务器使用本机 VPN

这份指南说明如何在本机开启 Clash/VPN 后，通过 SSH 隧道把本机代理转发到远程服务器。配置完成后，服务器上的 curl、pip、git、conda 等命令可以走你本机的代理出口。

核心思路

本机电脑 Clash/VPN 正在运行，监听 127.0.0.1:7897。
→
SSH 隧道 RemoteForward 7898 127.0.0.1:7897 把本机代理转给服务器。
→
远程服务器 服务器访问 127.0.0.1:7898，实际流量回到本机 VPN。

注意这里的 127.0.0.1 在不同位置含义不同：在本机 Clash 配置里，它指你的电脑；在服务器 .bashrc 里，它指服务器自己。SSH 的 RemoteForward 会在服务器上开一个本地端口，把它接回你电脑的代理端口。

准备条件

本机代理端口

确认 Clash 或其他 VPN 客户端的 HTTP/Mixed 代理端口。本文假设是 7897。

SSH 可连接

你已经能用 VS Code Remote SSH、PyCharm SSH，或命令行 SSH 连接服务器。

服务器允许转发

服务器 SSH 服务需允许 TCP 转发。大多数服务器默认可用。

为保护隐私，本文统一使用 <SERVER_HOST>、<SSH_USER>、<SSH_PORT> 这类占位符。不要把真实 IP、用户名、端口别名写进可公开分享的文档。

方法一：VS Code Remote SSH

在本机打开 SSH 配置文件，通常是 Windows 的 C:\Users\你的用户名\.ssh\config，或 macOS/Linux 的 ~/.ssh/config。添加一个脱敏后的模板：

Host <ALIAS>
    HostName <SERVER_HOST>
    Port <SSH_PORT>
    User <SSH_USER>
    RemoteForward 7898 127.0.0.1:7897
    ServerAliveInterval 30
    ServerAliveCountMax 3
Host 本机使用的连接别名，例如 gpu-server。可以随便命名，不需要等于服务器真实主机名。
RemoteForward 让远程服务器监听 127.0.0.1:7898，并把流量转发到你本机的 127.0.0.1:7897。
ServerAlive* 保持 SSH 连接活跃，减少长时间空闲后断开的概率。

然后在 VS Code 中执行 Remote-SSH: Connect to Host，选择 <ALIAS> 连接即可。只要这条 SSH 连接保持打开，服务器上的 127.0.0.1:7898 就会通向本机 VPN。

方法二：PyCharm 连接服务器

PyCharm 通常通过 SSH Interpreter、Deployment 或 Gateway 连接服务器。它不一定会直接读取 VS Code 的连接配置，所以建议优先复用系统 SSH 配置，或在 PyCharm 的 SSH 配置里补充隧道。

推荐做法：让 PyCharm 使用 OpenSSH 配置

  1. 先把上面的 Host <ALIAS> 写入本机 ~/.ssh/config。
  2. 在 PyCharm 里新增 SSH 连接时，选择或填写同一个主机别名。
  3. 连接成功后，在 PyCharm 的远程终端中执行本文后面的验证命令。

如果 PyCharm 不读取该配置

可以先用系统终端手动建立一条保持打开的 SSH 隧道，再让 PyCharm 正常连接服务器：

ssh -N -R 7898:127.0.0.1:7897 <SSH_USER>@<SERVER_HOST> -p <SSH_PORT>

其中 -R 与 RemoteForward 作用相同，-N 表示只建立隧道，不进入远程 shell。这个终端窗口保持打开时，服务器代理端口才有效。

在服务器上配置 .bashrc

SSH 隧道建立后，登录服务器，编辑 ~/.bashrc，添加：

# Use local machine VPN through SSH RemoteForward.
# Server-side proxy endpoint: 127.0.0.1:7898
export http_proxy="http://127.0.0.1:7898"
export https_proxy="http://127.0.0.1:7898"
export HTTP_PROXY="$http_proxy"
export HTTPS_PROXY="$https_proxy"

# Optional: keep localhost and private-network traffic direct.
export no_proxy="localhost,127.0.0.1,::1"
export NO_PROXY="$no_proxy"

让配置立即生效：

source ~/.bashrc

如果只想临时使用，不想长期写入 .bashrc，也可以直接在当前终端执行这些 export 命令。关闭终端后配置会失效。

验证是否成功

在远程服务器终端执行：

echo "$https_proxy"
curl -I https://www.google.com
curl https://ipinfo.io/ip

如果 curl 能正常返回，说明服务器已经通过 SSH 隧道走到了本机 VPN。也可以用下面的命令观察端口是否在服务器本地监听：

ss -lntp | grep 7898
常见失败原因
  • 本机 Clash/VPN 没有运行，或实际端口不是 7897。
  • VS Code / PyCharm 的 SSH 连接没有使用包含 RemoteForward 的配置。
  • 服务器 SSH 禁用了 TCP 转发，需要管理员检查 AllowTcpForwarding。
  • 远程服务器上已有程序占用了 7898，可以换成 7899 等其他端口，但 .bashrc 也要同步修改。

安全注意事项

  • 不要把真实服务器 IP、用户名、SSH 端口、Host 别名截图公开发给别人。
  • 服务器上的代理地址建议只监听 127.0.0.1，不要开放成 0.0.0.0。
  • 不要把代理配置写进项目仓库，除非里面没有个人信息，并且团队明确需要。
  • 多人共用服务器时，避免使用公共端口；建议每个人使用不同的远程端口，例如 7898、7899、7900。
  • 如果服务器环境需要审计网络出口，先确认这类代理转发是否符合团队或机构规范。

可直接复制的最小模板

本机 SSH 配置：

Host <ALIAS>
    HostName <SERVER_HOST>
    Port <SSH_PORT>
    User <SSH_USER>

服务器 ~/.bashrc：

export http_proxy="http://127.0.0.1:7898"
export https_proxy="http://127.0.0.1:7898"
export HTTP_PROXY="$http_proxy"
export HTTPS_PROXY="$https_proxy"

source ~/.bashrc
