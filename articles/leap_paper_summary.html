LEAP：用 Agentic 框架让通用 LLM 在形式化数学上起飞

一句话总结

TL;DR

论文提了一个叫 LEAP（LLM-in-Lean Environment Agentic Prover） 的智能体框架。 它只用通用大模型（论文里用的是 Gemini 3.1 Pro）做后端，不依赖专门微调的 prover， 通过"非形式蓝图 + 形式 sketch + Lean 编译反馈"的循环，把定理证明的搜索拆成一张 AND-OR DAG。

效果上：Putnam 2025 的 12 道题全部解出（与 Axiom3、Numina 等闭源系统持平）； 新发布的 Lean-IMO-Bench 上把通用 LLM 的单次形式化通过率从不到 10% 拉到 70%， 超过了 IMO 金牌系统 Aristotle 的 48%。

为什么这件事值得专门写一篇

过去一年形式化数学这条线几乎被"专门 prover"统治：AlphaProof、DeepSeek Prover、Seed Prover、 Goedel Prover V2…都是大成本微调出来的专用模型。LEAP 抛出的反问是——通用 LLM 真的不行吗？ 还是说我们没给它合适的脚手架？论文给出的答案是后者。

为什么做这个研究：非形式推理和形式推理的鸿沟

现状是：LLM 在自然语言数学（informal math）上已经非常强，AIME、IMO、Putnam 这些竞赛题已经能做对不少； 但同样的题要写成 Lean / Isabelle / Coq 这种机器可验证的形式化证明，性能就一落千丈。

作者引用了 Kepler 猜想作为引子：Hales 的证明人类审稿 4 年只能说"99% 把握"，最后又花了 10 年做形式化才彻底盖章。 这说明形式化是值得追求的——一旦写出来，机器就能机械地 100% 验证正确性。

业界的两类尝试

① 专门 prover 模型

在形式化语料上大规模微调：AlphaProof、DeepSeek-Prover V2、Seed Prover、Goedel-Prover V2。很强，但要大量算力和专门数据。

② 智能体 / 推理时搜索

Hilbert、AlphaProof Nexus、Aristotle、Seed Prover 1.5——非形式推理用通用 LLM，Lean 步骤仍依赖专门 prover。Axiom3 / Numina 解 Putnam 2025 但闭源，不可验证。

LEAP 的定位

两条路都不彻底：专用 prover 烧钱且难泛化；agent 类方法仍绑死在专门 prover 上。 LEAP 选了第三条路——纯通用 LLM + 精心设计的 agent 框架，证明"形式化数学的天花板，不应该被 prover 模型垄断"。

核心观点

通用 LLM 的瓶颈不是"读不懂 Lean 语法"，而是"在一次尝试里写出又长又复杂又正确的完整证明"。 一旦允许分解、迭代、反思，这些模型本来就有的强项（informal reasoning、instruction following、self-refinement）就会被释放出来。

LEAP 的核心想法

LEAP 的工作流几乎就是把数学家写证明的流程搬过来：

  1. 先在脑子里（或纸上）画一个高层蓝图：定理可以拆成哪几个引理？
  2. 按蓝图一段段写形式化证明。
  3. 写完一段就交给 Lean 编译器检查，错了就改，改不动就回去调整蓝图。

这个流程在形式化社区里早就有了：Lean Blueprint 工具就是干这个的， 费马大定理的多年形式化工程就是靠它组织的。LEAP 的创新是把这件事自动化：

三个相互咬合的设计选择

DAG 层次记忆化

证明过程不是树，是 AND-OR DAG。子引理可以被多个父节点共享，重复子问题不用反复证明。

非形式/形式交错规划

先写自然语言策略（informal blueprint），再转成 Lean sketch。LLM 负责想，Lean 负责验。

验证驱动的搜索

Lean 编译器做语法/类型检查；另一个 LLM 评审做"分解是否合理"的语义把关。

4.2 AND-OR DAG：为什么不是树

把证明组织成一张有向无环图（DAG），节点分两种：

  • OR 节点：开放的目标（theorem / lemma），任意一个有效证法都能解。
  • AND 节点：一个分解方案，需要它所有子目标都成立才有效。

DAG 相对树有两个关键优势：

  1. 单调细化（Monotone Refinement）：一旦某层分解确定，后面的工作只在该层下探索，不会推翻整体结构。
  2. 引理记忆化（Lemma Memoization）：同一个辅助引理在多个分支上被需要时，证一次就好，还能预判性地生成"未来可能用到"的引理，挂在 DAG 里待用。

4.3 形式 sketch 与 sorry 占位符

Sketch 是 Lean 的一种特殊写法：主体定理用真实证明，但其中引用的"待证子引理"用 sorry 占位。 只要 sketch 通过类型检查，就意味着"这些子引理一旦全部证完，父目标也就证完了"——这正是 AND 节点的语义。

4.4 验证的两层把关

  • Lean 编译器：检查 sketch / 证明是否类型正确、合法。
  • LLM 评审（Reviewer）：检查分解是否真正降低了难度。这一步很关键，否则容易出现"看起来分解了、其实没进展"的死循环（Figure 3 给了一个真实失败案例）。
论文 5.3 节重点分析了去掉 Reviewer 的失败：LEAP 在 Putnam A5 上 8 次 rollout 都做不出来；带 Reviewer 2 次就成功。 Reviewer 的作用是"早识别弱分解、触发回溯、把算力花在有希望的分支"。

4.5 搜索策略

目前实现是简单的 DFS + 回溯。作者明确说未来会探索 LLM 作为 search heuristic （分支优先级、分解策略选择、算力分配）。

新基准：Lean-IMO-Bench

MiniF2F 和 PutnamBench 都被刷得太"饱和"了，几乎所有新模型都能拿到 80%+。论文新发布了一个 Lean-IMO-Bench，专门挑 IMO 风格的题：题目陈述短，但证明往往要 多步、非常规、需要洞察。

数据集概况

  • 共 60 道题，分 Basic（30 道） 和 Advanced（30 道）。
  • 覆盖代数、组合、数论、几何四类，比较均衡。
  • 所有题都由 Lean 专家手工形式化，确保精度。
  • 支持三种任务：自然语言证明、形式化定理证明、形式化翻译（给非形式证明让模型转成 Lean）。

一个非常反直觉的现象：非形式证明能解 55% 的题，但同一道题让它写成 Lean，直接掉到 4.6%。 这不是"模型笨"，而是"它在没有结构化反馈的情况下，写不出又长又正确的形式化证明"。 这恰恰是 LEAP 要攻克的痛点。

消融与发现

7.1 单次 vs. 迭代：通用 LLM 真的"懂得"迭代

为了拆开"框架增益"和"模型本身"的贡献，作者做了一个有意思的实验： 把 LEAP 中的 Direct Formalization 路径单独拿出来，区分单次采样（Pass@128）和迭代修订（1 次初始 + 最多 20 轮编译反馈）。

模型单次 (Pass@128)迭代 (Pass@1)
Goedel-Prover-V2-32B10.0%6.6%
Gemini-3.1-Pro20.0%36.6%

看出两件事：

  • Goedel-Prover-V2 在迭代设置下反而下降，说明它"不会读编译器反馈"——纯合成数据的代价。
  • Gemini-3.1-Pro 几乎翻倍。这印证了 LEAP 的核心论点：迭代修订能力是通用 LLM 的强项，形式化数学要的不是更强的 prover，而是更好的循环。

7.2 DAG 记忆化到底贡献了多少

把 DAG 换成朴素树（仍然保留非形式/形式交错 + 编译反馈 + Reviewer），只去掉"全局引理共享"：

w/o DAG（朴素树）100 / 7575 / 25100 / 66.60 / 073.3 / 40.0

朴素树就已经把 Hilbert（36.6 / 6.6）远远甩开了——说明非形式/形式交错 + Reviewer贡献最大。 而 Full DAG 又在 Advanced 上把代数从 75→100、数论从 66.6→100，这是 DAG 记忆化在更难的题上带来的额外增益。

7.3 LLM Reviewer：值不值？

在 Putnam A5 上，有 Reviewer 时 LEAP 2 次 rollout 成功；去掉后 8 次 rollout 全部失败。 论文 Figure 3 给出了"为什么"的反例：模型提出一个分解，把 grandparent 目标展开、折叠，得到的子引理语法上和原命题完全一样—— 没有 Reviewer 它会一直重复这个无意义的展开直到算力耗尽。

图 3 案例的简化
-- 原始目标
theorem perms_a_equiv_b_card ... :
  Nat.card (PermsA m s k) = Nat.card (PermsB m s k) := by
  rw [← card_perms_a_eq, ← card_perms_b_eq]
  exact valid_perms_end_eq_sigma_card ...

-- 提出的"子引理"（实际上是同一命题换个写法）
lemma card_perms_a_eq_card_perms_b ... :
  Nat.card (PermsA m s k) = Nat.card (PermsB m s k) := by sorry

这种形式合法、语义无进展的分解是 agent 框架的典型陷阱，LLM Reviewer 正是用来识破它的。

案例研究：把 Knuth 猜想的关键子问题形式化

LEAP 团队还把它扔到了真正的开放问题上：Donald Knuth 提出的 有向 Cayley 图的哈密顿分解猜想—— Γₘ = Cay(ℤ₃ₘ, {e₁, e₂, e₃}) 能否被分成三个不同的哈密顿圈？

对 m = 2h ≥ 10（偶数情形）的非形式证明本身就巨复杂：组合分析、parity-dependent intervals、跨行 transition， 大约 20 页。

LEAP 选了其中一个关键子问题：验证 Color 2 子图的 2D 平面投影是一个长度 m² 的闭合圈。 最终它把这一段非形式证明拆成一张精细的 DAG，自主地把每个节点搞定， 输出了 5000+ 行 Lean 4 代码。

另一个案例是 Erdős 457：让 LEAP 从头推导一个已知的经典结果，验证它能"自主重建"前人证明。

这两件事放在一起的意思是：LEAP 不只是"竞赛玩具"，它能啃真正的研究级问题。 当然这两例都是作者团队深度参与选题的（Knuth 那例的非形式证明也是他们写的），离"无人监督"还有距离。

我的理解与评价

亮点

  • 视角更新：把形式化数学的瓶颈从"模型能力"重新定位为"工程结构"。这其实呼应了 LLM agent 整个领域近两年的共识：好脚手架 > 好模型。
  • DAG 记忆化是个真正有洞察的设计——它直接解决了 Hilbert 类系统的指数爆炸问题。
  • LLM Reviewer 这一步很优雅，把"语义进步 vs. 形式合法"区分开来，5.3 的失败案例讲得很清楚。
  • 新基准 Lean-IMO-Bench 选的方向对（短陈述、长多步证明），是后续工作的好工具。
  • 5000 行 Lean 4的 Knuth 案例，至少在"工程化"层面证明了规模化是可行的。

需要注意的局限

  • 几何是硬伤：所有方法（除 Aristotle 在 Basic 上靠专用工具撑到 16.7%）几乎全 0。这是 Lean 形式化几何本身没成熟，不是 LEAP 的锅，但确实限制了通用性。
  • 算力成本不低：Putnam 12 题累计 7700+ 次 LLM 调用，最难一道 3.0k 次。在没有价格披露的情况下，外人复现门槛不低。
  • Putnam A5 = 2000 行 Lean，已经接近真实研究级规模。Reviewer 仍然只是 LLM，未来在更深的 DAG 上是否还够用，是开放问题。
  • 基线对比：Hilbert 在 7 天限时下被砍掉了，可能不完全公平；Axiom3 / Numina 闭源无法直接对比；作者没和 AlphaProof 完整公开版本（如果有）比。
  • 模型绑定：实验只用了 Gemini 3.1 Pro，结论是否对其他通用 LLM 同样成立，没有 ablation。

延伸思考

几个值得跟的方向
  1. Hybrid 路线：作者在 5.4 提到但没做——通用 LLM 做高层规划、专门 prover 做局部 tactic 生成。直觉上能把两边的强项拼起来。
  2. Reviewer 升级：现在只是"是否真简化"的判定。能不能让 LLM 同时给"分解建议"？这等于让 LLM 当 search heuristic 而不只是 filter。
  3. 跨题迁移：DAG 里的引理能不能在题目之间共享？比如某道 IMO 的辅助引理，下次做 Putnam 还能直接用。这需要一套"引理库"。
  4. 人机协作：论文图 2 里那张 DAG 本身就是给人类看的蓝图，意味着人可以在中间插入自己的引理 / 修正方向。这条"AI 写稿、人审稿"的路线对真正的研究协作很有价值。

总结一下：这是一篇方法清晰、实验扎实、有真实研究级案例的工程型论文。 它的核心论点——"形式化数学的瓶颈不在模型能力，而在搜索结构"——是站得住脚的， 也给整个 ATP 社区抛出了一个非常值得认真对待的替代路线。
