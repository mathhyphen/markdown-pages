01背景：VAE 怎么了

标准 latent diffusion 模型（Stable Diffusion、DiT、SiT）的两阶段训练是这样的：

阶段一
训 VAE
图像 ↔ 紧凑 latent
→
阶段二
训 DiT
在 latent 上做 diffusion
→
推理
采样 → 解码
latent → 图像

这里有个很要命的问题：SD-VAE 是个老古董。 Stable Diffusion 那会儿 (2021) 用的是 KL-VAE，编码器是个 8× 下采样的卷积网络， 把 256×256×3 压成 32×32×4（潜空间维度只有 4）。

VAE 三大先天不足

  • 架构过时：卷积 + 8× 下采样，挤压了 backbone 设计的灵活性（你想换 ViT？难）。
  • 潜空间维度太低：4 维 channel 承载了全部图像信息，瓶颈明显。
  • 语义信息几乎为零：SD-VAE 在 ImageNet 上 linear probing 准确率只有 ~8%。说明它压出来的 latent 几乎不携带分类/语义信息，对下游任务很不友好。
反直觉的点
VAE 的训练目标就是"重建得越像越好"，所以它把所有带宽都用来记低层像素细节。 留给"语义"的部分基本被挤干了。这跟人类视觉系统的处理顺序（先语义后细节）正好反过来。

一个自然的问题：如果 generation 目标只是"画一张像猫的图片"，是不是必须先学会把猫"压缩"成 4 维 latent？ REPA 和 RAE 系列的答案都是：不需要。直接用高维的、已经会理解图像的表征就行。

02核心想法：Representation Autoencoders

RAE = 冻结的语义 Encoder + 训出来的 Decoder

思路简单到近乎偷懒：

E
冻结的视觉 Encoder
DINOv2-B / SigLIP2-B / MAE-B
hidden dim = 768
→
latent
高维语义潜空间
256 tokens × 768 dim
(远超 SD-VAE 的 4 dim)
→
D
训出来的 Decoder
ViT-XL

Encoder 直接从现成的 self-supervised 模型拿过来（参数全部冻住），只训 Decoder。 这样有两大好处：

  • 潜空间天生富含语义：DINOv2 的 latent 在 ImageNet linear probing 上准确率 ~84.5%，跟 SD-VAE 的 8% 形成碾压级差距。
  • 训练成本极低：Encoder 不参与梯度计算，也不用训整个 AE，只需训一个 Decoder。

Decoder 怎么训？

标准的重建目标：

L = L1 + LLPIPS + Ladversarial

即 L1 像素损失 + LPIPS 感知损失 + GAN 风格的对抗损失。 Encoder patch size = Decoder patch size = 16，256×256 的图会得到 16×16 = 256 个 token。

业界长久以来的假设是："语义 Encoder 太关注高层结构，丢失了底层细节，所以不适合做重建"。 RAE 用一个简单粗暴的事实推翻了这个假设：只要 Decoder 训得足够好（ViT-XL + 对抗损失），冻结的 DINOv2-B 照样能重建出比 SD-VAE 更清晰的细节。

03直接拿 RAE 训 DiT，行不行？

衡量一个 AE 合不合格，其实有两个维度：

  • Reconstruction：能不能把图重建回来？（上节已验证 ✓）
  • Diffusability / Generation：在这个 AE 的 latent 上做 diffusion 容易不容易？生成效果好不好？

很不幸，把 RAE 接到 DiT 上直接训，几乎不 work。 小模型 DiT-S 完全失败，大模型 DiT-XL 性能也远落后于 SD-VAE baseline。 作者把这个失败归因到三件事：

失败三连
  1. 标准 DiT 是为 低维 VAE token 设计的，直接喂 高维 RAE token 不消化。
  2. Diffusion 的 noise schedule 是为 VAE token 的数据分布调的，对 RAE 这种"语义稠密"分布不合适。
  3. RAE Decoder 是在 干净 latent 上训的，但推理时面对的是 diffusion 中间过程的 带噪 latent，存在 distribution gap。

下面三节是 RAE 这篇论文的真正核心 —— 怎么把这三件事一个个修好。

04三个关键解法

4.1 容量匹配：模型宽度 ≥ Encoder token 维度

第一个意外发现来自一个 toy 实验：只取一张图片，用 RAE 编码成 latent， 然后用 DiT 去过拟合这一张图，看能学多像。

结论相当反直觉：

  • 固定深度，把模型变宽 → 训练 loss 单调下降，采样质量随之提升
  • 固定宽度，把模型变深 → 几乎没收益

最关键的是，当宽度增加到 768（也就是 DINOv2-B 的 token 维度）时， 训练 loss 才能收敛到接近零；宽度不够时，loss 卡在一个显著高于零的平台上不去。

Figure 4 思想：过拟合单张图，宽度才是关键
图示：随着模型 hidden dim 增大，单图过拟合 loss 逐渐下降；但要接近 0，dim 必须 ≥ 768。

作者进一步用 DINOv2-S / B / L 编码 + DiT-S / B / L 训练， 跑全量 ImageNet 数据集也复现了同样的规律： 只有当 backbone 宽度 ≥ Encoder token 维度时，DiT 才开始正常收敛。

直觉解释： 数据 x 本来分布在一个高维空间的低维流形上， 所以生成模型传统上只需要在低维空间建模就够了。

但加噪后，分布被"扩散"到整个高维空间，模型的容量必须跟着抬高才能继续建模。 直观上，瓶颈从"理解流形结构"变成了"在高维空间里做插值"，对容量的需求本质性地变了。

这就是 RAE 1.51 FID 时代"DiT 变宽才 work"的根因。后面的 RAE v2 又发现，规模化下这个约束会显著弱化。

4.2 噪声调度对齐：依赖有效数据维度

Diffusion 的 timestep schedule 决定了模型在多大噪声水平下学习。 Stable Diffusion 3 提出了"timestep shifting"——把 schedule 往某一端推一推。 RAE 把这个思想落到自己身上：

对于 schedule \( t_n \in [0,1] \)，shift 后的 timestep 为 \[ t_m = \frac{\alpha \cdot t_n}{1 + (\alpha - 1) t_n} \] 其中 \(\alpha = \sqrt{m / n}\)，\(m\) 是 RAE 的有效数据维度（token 数 × token 维度）， \(n = 4096\) 是 SD3 的基准维度。

实验上这一招直接把 FID 拉低一大截。简单说：高维语义 latent 配低维 schedule 会让噪声加得"太快"， 模型大部分时间都在学"几乎纯噪声"，浪费算力。把 schedule 拉一下，让噪声加得"慢"一点， 模型才有时间学语义结构。

4.3 噪声增强 Decoder：让 Decoder 适应"带噪输入"

RAE 的 Decoder 是在干净 latent 上训的（直接来自 DINOv2）。 但 diffusion 推理时，DiT 在 t 大的时候输出的 latent 是非常带噪的。 这种 train-test mismatch 让 Decoder 容易崩。

解决思路：在训 Decoder 的时候，主动在 latent 上加少量高斯噪声： 

z_train = E(x) + ε,    ε ~ N(0, σ²I)
x̂     = D(z_train)

直观上：把 latent 的分布从"训练集样本点的离散集合"平滑成"附近的小球"， Decoder 见过"轻微偏移的输入"，推理时就不会被击穿。

副作用：rFID 略升高（重建质量轻微下降），但 gFID 改善（生成质量提升）。 这个 trade-off 在 RAE v2 里被证伪——规模化下这个 trick 几乎没用。

05DiTDH：浅而宽的接收头

既然"宽度 ≥ 768"是硬约束，朴素的方案就是把 DiT backbone 整体加宽到 1024 / 1536。 但 GFLOPs 会爆，训练成本受不了。

RAE 的解法是改造 backbone 的入口：保留 DiT 主干为相对窄的尺寸， 但在进入主干之前接一个浅而宽的"接收头"，论文里叫 DDT head。

结构示意

DiTDH 架构：宽 Head + 相对窄的 Transformer 主干
设计哲学：让"信息吞吐量瓶颈"在浅层就被打开，深层专注于组合语义。

为什么是"浅而宽"而不是"深而窄"？

  • 宽：hidden = 2048，能装下 768 维 token 携带的所有信息，不被压垮。
  • 浅：只有 2 层，FLOPs 增加有限，主干可以保持相对窄（比如 1152）。
  • 位置在前：先扩带宽再做语义组合；不然的话信息进入主干前就被切掉了。

实验上 DiTDH 比朴素加宽的 DiT 收敛更快、FID 更低。 一个有趣的副产物：如果用 SD-VAE（4 维 latent）跑 DiTDH，反而比标准 DiT 差。 说明这个 trick 只在"高维 latent"场景下才有用——和第 4.1 节的"容量匹配"是同一硬币的两面。

讨论：几个有意思的对照实验

  • raw pixel 当 latent 行不行？ 256×256 patch=16 → token dim 768，刚好凑齐。但 raw pixel 上训 DiT 比 DINOv2-B 的 RAE 差很多。说明"高维"不是充分条件，语义信息密度才是。
  • DDT head 是不是对 SD-VAE 也 work？ 不 work，反而更差。印证 DDT head 解决的是"高维 → 主干"的带宽问题，对低维数据是负担。
  • Encoder 选哪个？ DINOv2-B > SigLIP2-B > MAE-B。差别主要在重建质量上，生成 FID 接近。

07整条系列论文纵深

这一节把上面 6 篇论文的"它到底解决了什么 / 留下了什么"讲透，方便对照读。

DiT（2022.12）—— 把 Transformer 搬进 Diffusion

关键洞察：FID 与 GFLOPs 在 log-log 上是单调下降，这意味着 DiT 像 ViT 一样是"可扩展的"。这是后续所有工作的基础信心——花算力堆 GFLOPs 真的能换来质量。 论文还贡献了 adaLN-Zero Block（条件注入最高效的方式）。

SiT（2024.01）—— 把动力学换成 Flow Matching

SiT 不改架构，改的是训练目标。把 DDPM 换成 stochastic interpolant / flow matching， 多了几个独立可调的旋钮：interpolant 类型、连接分布、扩散系数、采样器。 论文的核心实证：DiT 时代的很多"魔法数字"在 flow 框架下都有更优选择。 RAE 直接继承了 SiT 的训练范式（用 flow matching 而非 DDPM）。

REPA（2024.10）—— 第一次把表征喂给 Diffusion

关键观察：DiT/SiT 的 hidden state 虽然也有判别能力（linear probe 60%+）， 但和 DINOv2（80%+）差距明显，且这个差距即使训 7M 步也填不上。

修法极简：加一个正则项，把 diffusion 中间层 hidden state 的投影向 DINOv2 的干净表示拉齐： 

L_total = L_diffusion + λ · || proj(f_θ(x_t, t)) − f_φ(x_clean) ||²

效果炸裂：SiT 训练加速 17.5×，FID 1.42。但 REPA 仍然依赖 SD-VAE 提供潜空间， DINOv2 只是"外挂的监工"。RAE 把这一步推到底——DINOv2 直接当主角。

RAE v1（2025.10）—— 替换 VAE

REPA 的下一步：如果 DINOv2 的表征这么好，为什么不让它直接当 AE 的 Encoder？ 这就是 RAE。论文还解决了三个工程难题：容量匹配、噪声调度、Decoder 噪声增强。 RAE 的隐含假设是"表征质量 ≈ 潜空间质量"，论文用一系列实验证明这个直觉是对的。

SRA（2025.05）—— 不要外部 Encoder

REPA / RAE 都依赖一个外部的 DINOv2。SRA 问：DiT 自己能不能当自己的监工？ 答案是可以。方法是把 DiT 早期 block（高噪声）的输出和晚期 block（低噪声）的输出做对齐。 隐含假设是：去噪过程从"高噪声的弱表征"到"低噪声的强表征"是单调进步的， 让浅层去模仿深层的语义结构，模型就能自我提升。

优势：彻底摆脱外部 Encoder，训练管线更简洁；劣势：对齐目标在 DiT 内部产生， 没有 REPA 那么强的"语义锚点"。

RAE v2（2026.01）—— 推到 T2I 规模 + 简化

RAE v1 的 ImageNet 实验只是 toy。RAE v2 把它推到 0.5B → 9.8B 参数规模， 干了两件重要的事：

  • 数据 scaling：Encoder 还是 SigLIP-2（冻结），但 Decoder 用 web / 合成 / 文字渲染数据继续训。 发现 scale 提升整体保真度，但针对性数据配比对特定能力（如文字渲染）才关键。
  • 设计简化：规模化下，"宽 DDT Head"和"噪声增强 Decoder"基本无收益。 唯一仍关键的是"维度感知调度"。RAE v1 的三大工程招数只剩一招。
  • 与 FLUX VAE 的正面对决：在 0.5B / 1.5B / 4B / 9.8B 四个规模上预训练，RAE 在所有规模上 FID 都低于 VAE。 微调阶段更夸张：VAE 训到 64 epoch 就灾难性过拟合，RAE 训到 256 epoch 依然稳定提升。
  • 统一表征空间的暗示：DINOv2 / SigLIP 是给理解任务用的，RAE 的 latent 也是这两者。 意味着同一个 latent 空间里，理解模型和生成模型可以直接对话——一个 unified model 的雏形。

08关键公式速查

F5. Theorem 1：toy 模型下宽度不足的 loss 下界

设 \(\mathbf{x} \sim p(\mathbf{x}) \in \mathbb{R}^n\)，\(\varepsilon \sim \mathcal{N}(0, I_n)\)， \(\mathbf{x}_t = (1-t)\mathbf{x} + t\varepsilon\)。 考虑函数族

\[ \mathcal{G}_d = \{ g(\mathbf{x}_t, t) = \mathbf{B} f(\mathbf{A}\mathbf{x}_t, t) : \mathbf{A} \in \mathbb{R}^{d \times n}, \mathbf{B} \in \mathbb{R}^{n \times d} \} \]

则对任意 \(g \in \mathcal{G}_d\)（其中 \(d < n\)）：

\[ \mathcal{L}(g, \theta) \geq \sum_{i=d+1}^{n} \lambda_i \]

其中 \(\lambda_i\) 是随机变量 \(W = \varepsilon - \mathbf{x}\) 协方差矩阵的特征值。

对"单图过拟合"这个特殊情形，\(p(\mathbf{x}) = \delta(\mathbf{x} - \mathbf{x}_0)\)， 退化为 \(W \sim \mathcal{N}(-\mathbf{x}_0, I_n)\)，\(\lambda_i = 1\)， 因此：

\[ \tilde{\mathcal{L}}(g, \theta) \geq \frac{1}{n} \sum_{i=d+1}^{n} 1 = \frac{n-d}{n} \]

这就是图 4 的"宽度不到 token dim，loss 卡在 (n−d)/n 的平台上"的数学解释。 当 \(d \to n\)，下界趋近 0，模型才能完全拟合单图。

t_shifted = (α · t) / (1 + (α − 1) · t)

09开放问题 & 讨论

Q1. 为什么 DINOv2 / SigLIP 这种"理解型"特征也能重建？

经典假设：理解 Encoder 丢弃了高频细节，所以重建差。 RAE 反驳了它，但并没有完全解释机制。可能的解释：

  • DINOv2 的中间层（含 patch token 之前的特征）仍保留了相当多空间细节，只是最终分类头把空间信息聚合了。
  • Decoder（ViT-XL）容量足够大，能从高维语义 latent 里"反推"出细节——本质上是用先验补全缺失。
  • 对抗损失在帮忙：它强迫 Decoder 输出"看起来真"的图片，本质上是在让 Decoder 学会 hallucinate 细节。

Q2. RAE 在 256 token × 768 dim 这种"高维稀疏"空间上 work，那更稀疏的呢？

比如 64 token × 1536 dim（信息密度更高）。或者反过来，4096 token × 48 dim（更多空间 token，更少语义）。 RAE v1 没系统探索。RAE v2 提到规模化下"高维约束"会弱化，但具体 sweet spot 没定。

Q3. RAE 的 latent 能跨模态用吗？

DINOv2 / SigLIP 都是视觉模型。RAE 复用它们的 latent，意味着 diffusion 的中间空间和理解模型 的中间空间是同一个。这是个 unification 的钩子：未来也许能用同一个 latent 做检测、分割、生成。 RAE v2 提到"多模态模型可以直接推理生成的 latent"，是这个方向的暗示。

Q4. RAE v2 抛弃了"宽 Head"和"噪声增强 Decoder"——这是不是说明 RAE v1 那些 trick 本质上是工程补丁？

可能的解释：当模型规模到 9.8B 时，主干本身已经有足够容量， 不再需要专门加宽的 Head。噪声增强 Decoder 的"必要性"也可能被大模型自己的 robustness 覆盖。 这暗示了一条经验法则：小模型靠架构 trick，大模型靠规模。

Q5. 如果 Sora / 视频生成也走 RAE 路线，会发生什么？

视频比图像难一个量级：需要时间一致性、需要大运动。VAE 当前的瓶颈在视频上更突出 （低维 latent 撑不住高帧率）。RAE 路线可能更值得做： 用 video-aware 的表征（如 VideoMAE）做 Encoder，配合 temporal-aware 的 Decoder。 目前没看到明确的工作，但 RAE v2 的 T2I 范式延伸很自然。

做实验时容易踩的坑

过来人经验
  1. DINOv2 不是所有尺寸都好用。DINOv2-S (384 dim) 太弱，DINOv2-L 训练成本高但提升边际。Sweet spot 是 B 或 L。
  2. SigLIP2 在 FID 上略输 DINOv2，但对文字理解类任务更友好。T2I 场景建议直接 SigLIP2。
  3. DDT Head 的 hidden dim 至少 ≥ 2 × Encoder token dim，否则带宽不够（论文：2048 ≈ 2.67 × 768）。
  4. 维度感知 schedule 别忘。直接拿 SD3 默认 schedule 用，FID 会显著变差。
  5. 噪声增强 Decoder 的 σ 别开太大。论文没给完整 sweep，从 0.05 ~ 0.1 开始试。
